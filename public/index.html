Lecture mode, or just speak your doubt.

Astra runs two modes. Lecture mode builds a narrated slide deck for a chapter — bullets, exact LaTeX, a key takeaway and a TTS-ready voice script per slide. Voice chat mode is the 1-on-1 doubt session: short spoken answers, the equation on screen while Astra talks, an exam-trap warning, and a follow-up question to check you actually got it.

How it works

POST /api/generate/lecture
  {"topic":"...","subject":"Physics","targetExam":"JEE Advanced","slideCount":7,"save":true,
   "provider":"ollama","baseUrl":"http://127.0.0.1:11434","model":"qwen2.5:3b-instruct"}

  -> the model is asked for strict LECTURE_MODE JSON
  -> fenced/partial output is extracted, validated and repaired (server/schema.js)
  -> voiceScript is forced TTS-safe: LaTeX is converted to phonetic text
  -> one automatic repair round-trip if the first answer breaks the contract
  -> deck is saved to public/content/<id>.json and appears in the library

POST /api/generate/practice   {"topic":"...","targetExam":"NEET","count":4,"focus":"..."}
POST /api/generate/validate   {"rawModelOutput":"...","kind":"lecture|practice"}   (browser-direct transport)
POST /api/decks               {"deck":{...}}                                       (save a previewed deck)

Browser-direct mode (Voice setup) makes the page itself call your local model — the right choice when Astra is served from a remote host but Ollama runs on your PC. Set OLLAMA_ORIGINS=* so Ollama accepts the request.

The JSON contract

Exactly two response shapes, exactly as specified. Wire your own frontend to these endpoints.

Endpoints

GET  /api/health                     -> engine, rule count, deck count
GET  /api/catalog                    -> all decks with slide counts
GET  /api/lecture?id=<deck-id>       -> MODE 1: LECTURE_MODE JSON
POST /api/doubt  {"message": "...", "history": [...], "contextTopic": "..."}
                                     -> MODE 2: VOICE_CHAT_MODE JSON
GET  /api/schema                     -> both contracts + a live example

GET  /api/providers/status           -> which local model the server can reach
POST /api/providers/test             -> probe an endpoint (also works browser-direct)
POST /api/generate/lecture           -> local model writes a new deck (+ validate/repair/save)
POST /api/generate/practice          -> local model writes MCQs for a topic or slide
POST /api/generate/validate          -> validate raw model output against a contract
POST /api/decks                      -> save a previewed deck into the library
POST /api/audio/tts                  -> local neural TTS (Piper / espeak-ng) -> WAV
POST /api/audio/stt                  -> local Whisper -> text
GET  /api/audio/status               -> detected local audio engines

Live-model mode: set OPENAI_API_KEY (optionally OPENAI_BASE_URL and ASTRA_MODEL) before npm start and /api/doubt is answered by the model using the same contract, with automatic fallback to the offline engine.
